# Nano-Jev v0.1 (research preview)

> **Version 0.1 — research preview.** Jev-style decision model. Independent; not affiliated
> with TypeSafe AI or the NanoJev GitHub project.

A tiny (22.7M parameter) **typed decision model for RAG pipelines**. Give it a question,
a set of options and some context; it returns a **calibrated probability for each option**
in about a millisecond on a GPU. It never generates text.

Code: [github.com/shubham10divakar/nano-jev](https://github.com/shubham10divakar/nano-jev)

| Decision | Type | Options | Input |
|---|---|---|---|
| `relevance` | score | irrelevant / partially relevant / directly answers | query + one passage |
| `sufficient` | yes/no | yes / no | query + several passages |
| `grounded` | yes/no | yes / no | claim + context |

| | |
|---|---|

| Training data | 49,760 examples: HotpotQA distractor (6,000 questions), SQuAD 2.0 (6,000), MultiNLI (8,000); seed 0 |
| Training | 2 epochs, batch 16 examples, AdamW lr 3e-5, weight decay 0.01, 6% warmup, linear decay, bf16 |
| Hardware / time | 1× NVIDIA RTX 3060 12 GB, 14.4 min |
| Calibration | Per-decision temperature: relevance 1.445, sufficient 1.378, grounded 1.234 (`calibration.json`) |
| Schema version | 0.1 (`nanojev_config.json`) |

## How it works

Each (question, option, context) triple is scored separately:

```
[CLS] question: <q> option: <opt> [SEP] <context> [SEP]  → encoder → linear → logit
```

A decision's option logits are divided by that decision's temperature and softmaxed.
Because options are scored independently, you can also pass **option sets it never saw
in training**. That works mechanically, but those probabilities are weak in v0.1.

## Usage

With the code from GitHub:

```python
from nanojev import Decider

d = Decider.from_pretrained("sdmlai/nano-jev", revision="v0.1")

d.relevance("When was UCL founded?", ["University College London was founded in 1826."])
# [{'irrelevant': 0.02, 'partially relevant': 0.04, 'directly answers': 0.94}]
d.sufficient(query, passages)   # {'yes': .., 'no': ..}
d.grounded(claim, context)      # {'yes': .., 'no': ..}
d.decide("Which topic is this passage about?", ["computing", "cooking"], text)
```

With plain `transformers` (no extra code):

```python
import json, torch
from huggingface_hub import hf_hub_download
from transformers import AutoModelForSequenceClassification, AutoTokenizer

repo = "sdmlai/nano-jev"
tok = AutoTokenizer.from_pretrained(repo, revision="v0.1")
model = AutoModelForSequenceClassification.from_pretrained(repo, revision="v0.1").eval()
temps = json.load(open(hf_hub_download(repo, "calibration.json", revision="v0.1")))

query = "When was UCL founded?"
passage = "University College London was founded in 1826."
question = f"How relevant is this passage to the query: {query}"
options = ["irrelevant", "partially relevant", "directly answers"]

enc = tok([f"question: {question} option: {o}" for o in options], [passage] * len(options),
          truncation="only_second", max_length=512, padding=True, return_tensors="pt")
with torch.no_grad():
    logits = model(**enc).logits.squeeze(-1)
probs = torch.softmax(logits / temps["relevance"], dim=0)
print(dict(zip(options, probs.tolist())))
```

Question templates for the built-in decisions:

| Decision | Question |
|---|---|
| relevance | `How relevant is this passage to the query: {query}` |
| sufficient | `Does the context contain enough information to answer: {query}` (context = passages as `[1] title: text` lines) |
| grounded | `Is this claim supported by the context? Claim: {claim}` |

## Results

Test split = held-out halves of the HotpotQA / SQuAD 2.0 / MultiNLI validation sets. Every
model is temperature-calibrated on the same calibration split. Accuracy (macro-F1):

| Decision | **Nano-Jev v0.1** (22.7M) | bge-reranker-v2-m3 (568M) | Qwen3-4B-Instruct, prompted (4B) | untrained base |
|---|---|---|---|---|
| relevance (3-way) | **0.798** (0.764) | 0.694 (0.618) | 0.660 (0.602) | 0.273 |
| sufficient | **0.759** (0.758) | 0.692 (0.692) | 0.706 (0.701) | 0.503 |
| grounded | 0.804 (0.804) | 0.798 (0.798) | **0.844** (0.844) | 0.540 |

Calibration error (ECE, after temperature scaling): relevance 0.020, sufficient 0.019, grounded 0.045.

Speed (ms per decision, batched, RTX 3060): Nano-Jev 0.6–2.3, bge-reranker 3.5–15.4,
Qwen3-4B 54.5–379.1 (Nano-Jev is ~90–165× faster than the LLM).

Full tables and method: [results/v0.1_comparison.md](https://github.com/shubham10divakar/nano-jev/blob/main/results/v0.1_comparison.md).

## Limitations (read before using)

- **In-distribution evaluation only.** The model was trained on the train splits of the
  same three datasets it is tested on; the baselines are zero-shot. There are no
  out-of-distribution results yet (planned for v1.0).
- **Groundedness** is below a prompted 4B LLM. Consider escalating low-confidence
  `grounded` decisions to a larger model.
- **English, Wikipedia-style text.** Expect worse behaviour on other domains and languages.
- **Thresholds don't transfer.** Re-check your probability thresholds on your own data.
- **Custom option sets** work but aren't trained for; treat those probabilities as rough.
- Relevance labels follow HotpotQA rules: "partially relevant" = a supporting paragraph
  that doesn't contain the answer string.
