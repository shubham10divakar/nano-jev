# Nano-Jev v1.0 results (2026-09-25)

v1.0 replaces the v0.1 base model (`cross-encoder/ms-marco-MiniLM-L6-v2`, MS MARCO lineage)
with a clean-licence base, adds evaluation on held-out datasets, and adds a confidence
cascade. v0.1 stays available unchanged (HF tag `v0.1`).

**Protocol.** Every model's temperature (and each baseline's score→option mapping) is fitted
on the in-distribution calibration split (`data/calib.jsonl`) and applied **unchanged** to
both test sets. Accuracy is after calibration. Speeds are batched throughput on an RTX 3060.

## 1. Choosing the base (all trained the same way: 3 epochs, lr 5e-5, best epoch kept)

| Candidate | Params | Licence | Best dev NLL | Test acc rel / suff / grd | Held-out acc rel / suff / grd |
|---|---|---|---|---|---|
| `nreimers/MiniLM-L6-H384-uncased` | 22.7M | MIT | 0.564 | 0.764 / 0.730 / 0.754 | 0.582 / 0.628 / 0.653 |
| `google/electra-small-discriminator` | 13.5M | Apache-2.0 | 0.495 | 0.770 / 0.783 / 0.802 | 0.569 / **0.692** / 0.651 |
| **`microsoft/MiniLM-L12-H384-uncased`** → **v1.0** | 33.4M | MIT | **0.429** | **0.815 / 0.845 / 0.844** | **0.635** / 0.670 / **0.675** |
| *(v0.1: `cross-encoder/ms-marco-MiniLM-L6-v2`)* | 22.7M | Apache-2.0 + MS MARCO | 0.491 | 0.798 / 0.759 / 0.804 | 0.631 / 0.680 / 0.672 |

Excluded: `BAAI/bge-small-en-v1.5` (MIT, but fine-tuned on data including MS MARCO) and
`microsoft/deberta-v3-xsmall` (8× slower here and NaN loss in bf16). All three candidates
peaked at epoch 2. Per-candidate tables: [`v1.0/candidates/`](v1.0/candidates/).

The like-for-like comparison (MiniLM-L6 with vs without MS MARCO pretraining: 0.798 vs 0.764
on relevance) shows the MS MARCO start was worth ~3–5 points; the deeper clean base more
than recovers it.

## 3. Held-out datasets (never used for training or calibration)

MuSiQue dev (multi-hop QA, hard retrieved distractors): relevance on 1,000 questions and
sufficiency on its 2-hop questions. VitaminC test (contrastive claim verification):
groundedness, 1,000 balanced claims. Built by `scripts/prepare_data.py --heldout`.

| Decision | **v1.0** | v0.1 | bge-reranker-v2-m3 | Qwen3-4B-Instruct prompted |
|---|---|---|---|---|
| relevance (MuSiQue, n=4,655) | **0.635** | 0.631 | 0.478 | 0.503 |
| sufficient (MuSiQue 2-hop, n=1,040) | 0.670 | **0.680** | 0.597 | 0.653 |
| grounded (VitaminC, n=1,000) | 0.675 | 0.672 | 0.737 | **0.787** |
| ECE (rel / suff / grd) | 0.174 / 0.183 / 0.166 | 0.163 / 0.081 / 0.177 | 0.322 / 0.109 / 0.025 | 0.222 / 0.115 / 0.073 |

Findings:
- Every model loses accuracy on unseen data. Nano-Jev drops ~15–20 points but still
  **leads on relevance and sufficiency**, where the reranker and the prompted 4B LLM fall
  further.
- **Groundedness transfers worst for Nano-Jev**: VitaminC's contrastive claims need more
  reasoning than a 33M model learned from MultiNLI. The LLM leads by 11 points.
- **Calibration fitted in-distribution is overconfident on new data** (ECE 0.17–0.18 for
  v1.0). Users should re-fit temperatures on a few hundred of their own labelled examples.

## 4. Grounded cascade: Nano-Jev v1.0 → Qwen3-4B

Accept Nano-Jev when its top probability ≥ t, otherwise use Qwen3-4B. t = 0.80 was chosen
on the calibration split (best calib accuracy, ties → fewer escalations). Full sweep:
[`v1.0/cascade/cascade.md`](v1.0/cascade/cascade.md), plot: [`v1.0/cascade/cascade.png`](v1.0/cascade/cascade.png).

| | escalated (test / held-out) | test acc | held-out acc | ms/decision (test) |
|---|---|---|---|---|
| Nano-Jev only | 0% / 0% | 0.844 | 0.675 | 1.0 |
| **cascade t = 0.80** | 26% / 30% | **0.868** | 0.745 | 13.8 |
| cascade t = 0.90 | 46% / 53% | 0.858 | 0.788 | 23.9 |
| cascade t = 0.95 | 72% / 72% | 0.852 | **0.794** | 37.3 |
| Qwen3-4B only | 100% / 100% | 0.844 | 0.787 | 51.3 |

- In distribution, the cascade **beats both models alone** with a quarter of the LLM calls.
- Out of distribution, t = 0.90 matches the LLM alone with about half the LLM calls, and
  t = 0.95 slightly beats it.
- This reproduces the JEV-as-a-Judge finding (accept when confident, escalate when unsure)
  with a 33M open model.

## 5. Other changes and caveats

- **Custom option sets regressed.** On an unseen topic question (`decide`), v1.0 ranks
  "cooking" (0.37) above "computing" (0.27); v0.1 gets it right (0.78). v0.1's MS MARCO
  base had learned general text–label matching that the clean base lacks.
- CPU speed (Ryzen 7 5800X, 8 threads): v1.0 ~17 ms/decision, v0.1 ~9 ms.
- A bug in the first held-out Qwen run (full-vocabulary logits at every position) overflowed
  the 12 GB GPU into system RAM; fixed with `logits_to_keep=1`, outputs verified identical.

## Reproduce

```powershell
python scripts/prepare_data.py --heldout --out data_heldout
python scripts/train.py --base microsoft/MiniLM-L12-H384-uncased --epochs 3 --lr 5e-5 --out runs/nano-jev-dev
python scripts/evaluate.py --model runs/nano-jev-dev --name test
python scripts/evaluate.py --model runs/nano-jev-dev --name heldout --test-data data_heldout
python scripts/baselines.py --which all --test-data data_heldout --suffix _heldout     # ~45 min
python scripts/cascade.py --model runs/nano-jev-dev --test-data data data_heldout --out results/cascade
```
